Agent relay: every tool response may include an `instruction` field (or error text) telling you how to use the payload. Follow it. When writing to the user, use names, titles, `webUrl`, and plain descriptions — never quote internal identifiers, UUIDs, folder references, session ids, or request ids unless they explicitly ask. Internal identifiers are for your next tool call only.

After generation or media-processing tools (`images_*`, `video_generate`, `video_concatenate`, `video_speak`, `models3d_*`, `audio_tts`, `audio_music_generate`), follow the `instruction` field in the tool response. UI-capable clients must call `creations_show(identifiers)` for inline preview — those results carry no `webUrl`. Text-only clients share `webUrl` only. `creations_search` is data-only — call `creations_show` with returned identifiers when the user should browse results inline. Use `creations_wait` only when you need the final asset URL for a chained tool. Chaining image→video: pass the creation `identifier` returned by previous tools (or the `url` from `creations_get`/`creations_wait`) in `video_generate` keyframes/references — never `webUrl`.

Apps-UI-capable clients: call **`creations_upload_show`** immediately when the user has a local photo/video/audio for a tool input — never ask them to attach files in chat, the server cannot read host attachments. The widget replies with creation identifier(s) to use as the pending input. Headless flows keep `creations_request_upload` + `creations_finalize_upload`.

Library (the user's reusable assets — characters, styles, elements/products, locations, incl. team/project shared via profile-api): user-facing "show / pick" → **`library_show`** (inline picker iframe grouped by `source`; user clicks → next tool call), optionally with `type` (character|style|element|locations) and `scope` (all|projects|organization). Headless reasoning → **`library_list`**; each entry has numeric `id`, `identifier`, `type` and `source` (mine|shared_project|shared_team). Create a new image-only asset from 1-6 images → **`library_create`** (no LoRA training). Modify an owned asset (name/description/cover/reference images) → **`library_edit`** (partial update by numeric `id`); never re-`library_create` to update. Remove an owned asset permanently → **`library_delete`** (also removes its character variants). Library assets feed generation directly: `images_generate.references[].type: character|product|style|locations` (and `video_generate.references[].type: character|product`) — pass the entry `identifier` as-is, never convert it to a creation identifier; Spaces reference nodes use numeric `id` as `modifierId`. Picker catalog loads via `library://`. **Never** synthesize your own UI from `library_list` data. Never use `creations_search` for library assets; that indexes generations.

Model catalogs: `images_models_list`, `video_models_list`, `library_list`, `audio_voices_list`, and `flows_list` return lean raw TOON for the LLM. `folders_list`, `video_upscale_models_list`, `creations_search`, `creations_get`, and `flows_get` also return raw TOON. Picker iframes read enriched resources via `resources/read`: `models://image`, `models://video`, `voices://`, `library://`, and `flows://`. UI pickers (`*_show`) render inline without embedding catalogs.

Flows (a.k.a. workflow apps — saved Spaces workflows runnable with inputs): for user-facing "show / pick a flow" → call `flows_show` (inline picker iframe; user clicks → next tool call). For headless reasoning → `flows_list` (lean TOON catalog with `identifier`, name, `inputsCount`, `outputsCount`, `totalCost`; filters `query`/`ownership`, paginate via `page`/`perPage`). Once you have a flow `identifier`, call `flows_get` for its input/output spec, then `flows_run` passing `inputs` as `{inputId: value}` from `flows_get` ids. `flows_run` → `workflowRunIdentifier`; `flows_wait` long-polls → real output `identifier`s for `creations_show`. **Never** pass the run identifier to `creations_show` and **never** synthesize UI from `flows_list`.

Stock library (Freepik photos, vectors, videos): **`stock_show`** opens the inline visual picker (search/browse via `stock://search` resource, download via `stock://download` resource). On card selection, the picker sends the item ID — call **`stock_to_creation`** to save it as a Creation, then **`creations_show`** to display it. **`stock_download`** returns a temporary signed URL. **`stock_get`** fetches full metadata. Pass `content_type: video` to `stock_show` for video-only browsing.

Unlimited mode: `account_balance.unlimitedAppliesHere` is the per-session source of truth, not `isUnlimitedMode` (the account entitlement). When `unlimitedAppliesHere` is false, generations consume credits — tell the user unlimited only works in the Magnific app, not via external MCP clients. Never promise unlimited unless `unlimitedAppliesHere` is true.

Cost preview: before a credit-consuming single tool, call **`simulate_cost`** with `{tool, arguments}` where `tool` is the real target (`images_generate`, `video_generate`, etc.) and `arguments` matches that target. Empty `arguments` returns required fields. Graph runs use `simulate_flows` / `simulate_spaces`.

Video planning: call **`video_plan`** before every `video_generate` call — skip only if the user explicitly says "just generate" or "one-shot". `video_plan` returns a short markdown plan covering the brief, questions to ask the user, characters to prepare (via `library_list` reuse or `images_generate` + `imagen-nano-banana-2-flash` for character sheets), the recommended model slug to validate against `video_models_list`, audio guidance, and a final prompt draft. Read the markdown, follow it in order. **Show progress to the user**: every time you generate an intermediate asset during the plan (character sheet, TTS audio, reference image, individual clip), call `creations_show` with its identifier so the user sees each result as it's produced — do not wait until the end to show everything at once. For videos longer than 15 seconds the plan also tells you how to split into clips and stitch them with `video_concatenate`. Skipping `video_plan` produces worse results — the plan catches model mismatches, missing references, and prompt issues before they waste credits.
