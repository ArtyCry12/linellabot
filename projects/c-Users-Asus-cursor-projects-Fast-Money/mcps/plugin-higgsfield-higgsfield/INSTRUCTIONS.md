Use generate_image, generate_video, and generate_audio as the core tools for image, video, and audio creation. Use generate_3d to turn an image into a 3D GLB mesh. When unsure which generation model fits, call models_explore(action:'recommend') with the user's goal and input context before calling a generate_* tool. For edits to an existing asset, prefer the dedicated tool over re-generating with a model: upscale_image / upscale_video (enhance or increase resolution to 2K/4K), outpaint_image (expand or uncrop an image), reframe (change a video's aspect ratio), remove_background (cutout / transparent background), motion_control (recast / puppeteer / motion transfer). Use virality_predictor when the user asks to predict video virality or analyze engagement, attention, audience response, retention risk, hook strength, or creative performance. Before creating or editing any browser game, call get_game_creation_instructions. When those game instructions require a bundled reference, script, or scaffold file, call get_game_creation_bundle_file. Before building any multi-step, made-to-brief video from a user request — a narrated explainer or story video, an ad / commercial, a UGC / talking-head video, a podcast, and similar templated video workflows — call get_workflow_instructions first (with no argument) to see the catalog of available workflows and their triggers, then call it again with the matching workflow name to load its instructions. New workflows are discovered from the catalog, so always check it rather than assuming which exist. When a loaded workflow requires a bundled template, reference, or script file, call get_workflow_bundle_file. When an Apps UI-capable client user has a local photo/image/video/audio for Higgsfield generation input, immediately call media_upload_widget; do not ask them to attach local media in Claude chat because remote MCP tools cannot read those attachments. For voice creation, use create_voice instead. For voice creation in Apps UI-capable clients, call create_voice immediately when the user asks to create a voice or says to call the Create Voice tool and the prompt does not already include audio_media_id. Do not ask the user to provide an audio file or name in chat first; the UI collects the required name, records or uploads audio, confirms it, and creates the voice itself — and if the user is out of credits or on a free plan it shows the plans/credits UI inline. After the widget reports the created voice you do not need to call create_voice_from_confirmed_audio again. Only call create_voice_from_confirmed_audio directly when the prompt already includes a confirmed audio_media_id and name. When the user provides a web media URL, call media_import_url first and pass the returned media_id to generation; never pass raw URLs in params.medias[].value. Use media_upload/media_confirm only when the client can upload bytes to the returned upload_url. For general files (archives, documents, code) the widget is not available; if you have the file bytes or can produce them (e.g. in a code execution environment), call media_upload with the filename, PUT the bytes to the returned upload_url yourself, then call media_confirm with type 'file' and share the returned url.
