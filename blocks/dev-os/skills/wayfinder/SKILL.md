# Wayfinder (карта решений)

**Upstream:** https://github.com/mattpocock/skills (MIT), skill `engineering/wayfinder`.  
**Adapter, не клон:** одна карта → сразу WBS. Без GitHub/Linear, без папки билетов,
без Claude slash-commands. На русском.

## Когда

- Новый проект / greenfield / «с нуля».
- Кусок работы не влезает в одну сессию — сначала найти маршрут, не ломиться в код.

## Когда НЕ

- Задача на одну сессию и уже ясна → grill-rounds или сразу WBS.
- Карта уже есть → не плодить вторую.
- Workspace — хаб `C:\Users\artyo\.cursor` — карту писать в **целевой** репо.

## Карта (один файл)

Путь: `docs/wayfinder.md` в целевом репо (или `WAYFINDER.md`, если `docs/` нет).

```markdown
## Цель
<1–2 строки: что должно получиться>

## Открыто
- [ ] <решение, которое ещё не закрыто>
- [ ] <следующее, если не зависит от предыдущего>

## Решено
- <вопрос> → <ответ одной строкой>

## Вне области
- <сознательно не делаем>
```

В «Открыто» только то, что можно сформулировать резко. Туман — не превращать в пункты.

## Поведение

1. Назвать цель. Scope карты = эта цель.
2. Выписать фронтир решений (не зависят от ещё открытых).
3. Закрыть фронтир: факты ищи сам; решения — через grill-rounds / AskQuestion.
4. Когда открытых пунктов нет или осталось меньше трёх и маршрут ясен — **сразу**
   `skills/task-decomposition/SKILL.md` (WBS). Не вести многосессионный трекер билетов.
5. Если репо не хаб — прочитать `blocks/dev-os/skills/project-context/SKILL.md`
   и при необходимости короткий `CONTEXT.md` (глоссарий).

## Не делать

- Не создавать `docs/wayfinder/NNNN-*.md` и не делать «один билет = одна сессия».
- Не требовать GitHub/Linear.
- Не заменять WBS.
- Не писать карту в хаб.
- Не клонировать mattpocock pack и не восстанавливать карантин как CORE.

## Связки

- Route `from-scratch` → этот skill.
- Дальше: grill-rounds (если ещё не было) → WBS.
