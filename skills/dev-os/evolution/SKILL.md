# Dev OS — Long-Term Evolution

Parent: [../SKILL.md](../SKILL.md) · Canon: `ai-tracking/dev-os/policies/evolution-principles.md`

**Permanent policy (DEC-007).** Not one-time tasks.

## When to load

- Phase 5+ execution between user tasks
- Post-milestone self-improvement
- Hub audit, cleanup, tool evaluation
- Any "should we adopt X?" question

## Rules

1. **Evidence first** — research, testing, or repeated practice before change
2. **No unnecessary changes** — stability over novelty
3. **Candidate A stable** — architecture changes need DEC + strong evidence
4. **Autonomy bounded** — safe improvements autonomous; integration/ship escalates

## Ten principles (summary)

| # | Area | Autonomous safe work |
|---|------|-------------------|
| 1 | Knowledge | dedupe, archive, layer updates, validated LTM |
| 2 | Performance | measure, propose, apply safe routing/cache tweaks |
| 3 | Tools | research + compare; **no auto-adopt** |
| 4 | QA | audit, fix docs/refs/dead files |
| 5 | Portability | keep corpus/skills platform-agnostic where possible |
| 6 | Maintenance | naming, folders, archive |
| 7 | Ecosystem | MCP health checks, registry sync |
| 8 | Market intel | research reports to corpus |
| 9 | Communication | improve doc/prompt clarity |
| 10 | Self-evolution | post-milestone lessons → backlog |

## Cadence (suggested)

| Cycle | Action |
|-------|--------|
| Per milestone | backlog review, proposed-insights triage |
| Monthly | ecosystem health (MCP status scripts), QA spot-check |
| On trigger | Candidate B/C from design-candidates.md |

## Outputs

- Changes → corpus/layers/skills (not architecture)
- Recommendations → `evolution/backlog.md` or DEC log
- Reports → `research/in-progress/` or domain findings
