# Урок: авто-роутинг и как просить «учителя промтов»

**Дата:** 2026-07-10  
**Сессия:** Task Router (DEC-057) + настройка Prompt Engineering Coach  
**Промтов разобрано:** 2 (твои, из этого чата)

---

## Что сработало

1. **Ты описал продукт целиком** — «хочу чтобы система сама распознавала задачу и вела к скиллам/MCP» — это сразу понятная постановка, не «сделай умнее».
2. **Во втором промте ты задал формат урока** — brief, без AI-эффекта, хуки в конце, один идеальный пример. Коучу не пришлось угадывать.
3. **`/autopilot` + длинное ТЗ** — правильная связка: права на действия + что именно построить.

## Что мешало LLM

1. **Очень длинный промт без «сделай X за один проход»**  
   Ты написал много «как должно быть в идеале» — это хорошо для видения, но агент может начать планировать вместо сборки.  
   → Лучше в конце одна строка: «собери и примени в систему сейчас».

2. **Опечатки в важных словах** (`promt`, `обчные`, `рассчитывай`) — модель всё равно понимает, но в **хуках системы** лучше писать `prompt` и `autopilot` как в командах.

3. **Два больших запроса подряд без приоритета** — сначала роутинг, потом coach. Агент сделал по очереди, но если срочно одно — напиши: «сначала только coach, роутинг потом».

## Было → лучше

| Было | Лучше |
|------|-------|
| «доработай идею и примени в систему» | `!auto собери task-router: hook + routes.json + rule. Reload не нужен объяснять — только список файлов.` |
| Длинное описание формата урока в чате | «Настрой prompt-coach по моему формату из Notion 📚 + шаблон brief» + ссылка на страницу |
| «чтобы не были часто уроки» | «урок не чаще 1 раз в 2 дня, только если 4+ моих промта» — **ты так и сказал, это отлично** — зафиксировано в `GATING.md` |

## Хуки — говори так, система поймёт сразу

| Скажи | Что произойдёт |
|-------|----------------|
| `!auto …` / `/autopilot` | Полная автоматизация, меньше вопросов |
| `/route проверь seo` | Покажет куда роутится запрос (task-router) |
| `урок промта` / `/prompt-lesson` | Принудительный brief-урок |
| `prompt-coach-status` | Готов ли следующий урок |
| `запомни …` | user-memory + squad-memory |
| `P3 test` | Автотесты хаба |
| `post reload` | Чеклист после Reload Window |

Полный список: `ai-tracking/PROMPT-HOOKS.md` · авто-ключи: `lib/task-router/routes.json`

## Фишка под тебя

Ты часто даёшь **mega-ТЗ** (Notion, пересборка `.cursor`, coach). Добавляй в конец **три строки контракта**:

```
Deliverables: <файлы/папки>
Не трогать: <mcp.json, коммиты, …>
Готово когда: <0 FAIL в тесте / могу reload и пользоваться>
```

Модель перестаёт «улучшать лишнее».

## Идеальный промт (пример)

```
!auto Настрой prompt-engineering-coach:
- захват моих промтов через hook
- урок brief в ai-tracking/prompt-lessons/ когда 4+ промта и 2+ дня
- стиль: простой язык, без AI-slop, хуки + 1 идеальный промт в конце
- Notion hub: 📚Мой promt-engineering (cross-link по запросу)

Не пиши урок сейчас — только систему.
Покажи: prompt-coach-status.ps1 после reload.
```
